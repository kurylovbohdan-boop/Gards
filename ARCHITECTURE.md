# GARDS 2.0 — концепт, архитектура, состояние, API

## 0. Концепт

**«Gards Outdoor Hub»** — единый магазин с четырьмя «мирами» (Рыбалка / Оружие и самооборона / Пиротехника / Туризм и спорт), у каждого свой акцентный цвет, но общий каркас: сине-серая база, чистый белый фон, яркие акционные плашки.

Три «вау»-механики, которых нет у Salmo.lv:
1. **3D-энциклопедия рыб** → фильтр каталога («выбрал щуку на Даугаве — получил подборку»).
2. **Остатки по магазинам в реальном времени + Pick Up in 1 Hour.**
3. **AI-помощник «Gards Meistars»** — 3 вопроса → готовый комплект в корзину.

> ⚠️ Юридически важно (LV): продажа оружия, средств самообороны и пиротехники регулируется законом. Нужны: **возрастной гейт 18+ / 21+**, проверка разрешений/лицензий на этапе оформления заказа, выдача оружия только в магазине (без доставки курьером), запрет рекламных акций «подарок» на часть категорий. Эти хабы — в отдельном раздел-режиме «Regulated», с обязательным подтверждением возраста. Это нужно согласовать с юристом GARDS до запуска.

## 3. Листинг каталога

- **Слева (desktop) / drawer (mobile):** фильтры — бренд, цена (range), наличие *«в магазине X»*, **целевая рыба** (из энциклопедии), тип водоёма, длина/тест/действие (для удилищ), диаметр/нагрузка (для лесок), цвет, рейтинг.

## 5. Схема состояний

### 5.1 Слои

| Слой | Инструмент | Что хранит |
|------|-----------|------------|
| Серверные данные | **TanStack Query** | товары, остатки, магазины, календарь клёва |
| Клиентский UI-стейт | **Zustand** | выбранная рыба, водоём, hotspot, тема, язык, корзина |
| URL-стейт | Next.js `searchParams` | фильтры каталога (шарится ссылкой) |
| Персист | `localStorage` | корзина, избранное, сравнение, тема |

### 5.2 Поток «Рыба → Товары»

```
[3D Canvas click on fish mesh]
        │  setFish('pike')
        ▼
 useFishStore  { fishId, waterType, waterBody, activeHotspot, budget }
        │
        ▼  derived key
 useGearMatch(fishId, waterType, waterBody)
        │  TanStack Query: ['gear-match', fishId, waterType, waterBody]
        ▼
 GET /api/gear-match?fish=pike&water=river&body=daugava&lang=lv
        │
        ▼
 { rods:[…], lures:[…], lines:[…], meta:{ lineDiameterMm:[0.18,0.28], … } }
        │
        ▼
 <GearPanel/> (3 вкладки) → «Показать все в каталоге» → /zveja?fish=pike&water=river
```

- Переключение водоёма **не перезагружает** модель — меняется только ключ запроса; `keepPreviousData` убирает мерцание.
- Hotspot «рот» → подсвечивает вкладку *Приманки*; hotspot «спина» → показывает глубину и сезон (из `FISH_DATA`).

### 5.3 Правила подбора (серверная сторона)

Таблица `fish_gear_rules`: `fish_id, water_type, category, attr_filters (jsonb), priority`.
Пример для щуки/река: удилище — спиннинг, тест 10–40 г, длина 2.4–2.7 м; приманки — воблеры/блёсны 8–18 см; шнур — 0.20–0.30 мм + флюорокарбоновый/стальной поводок.
Сервер превращает правила в SQL/Elasticsearch-запрос по атрибутам товаров. Правила редактируются из админки без деплоя.

## 6. API (контракты)

```
GET  /api/search/suggest?q=&lang=            → товары (превью, цена, остаток), категории
GET  /api/products?category=&fish=&water=&inStock=&store=&sort=&page=
GET  /api/products/:slug
GET  /api/products/:id/stock                 → [{storeId, name, qty, status, pickup1h, leadTimeH}]
GET  /api/gear-match?fish=&water=&body=&budget=
GET  /api/stores                             → список + координаты + часы работы
POST /api/pickup/reserve                     → {productId, storeId, qty} → резерв на 1 ч
GET  /api/fishing-forecast?body=&date=       → луна, T воды, индекс клёва
POST /api/assistant/kit                      → {target, place, budget} → комплект
GET  /api/pyro/:id/effect                    → видео/параметры (высота, диаметр, секунды)
```

**Остатки в реальном времени:** источник — складская система/POS (1С/Directo/…); шина — webhook → Redis (TTL 30–60 с) → SSE/WebSocket на клиент. Статусы: `>5`, `1–5`, `0 / под заказ 24ч`. Точные числа показываем только до порога.

**Pick Up in 1 Hour:** атомарный резерв (`stock_reservations`, TTL 60 мин), SMS/e-mail с кодом, авто-отмена по таймеру. Недоступно для regulated-категорий.

## 7. Остальные фичи (кратко)

- **AI «Gards Meistars»:** 3 шага (кого / где / бюджет) → `POST /assistant/kit` → серверный подбор через те же `fish_gear_rules` + LLM только для формулировки совета (цены и остатки — всегда из БД, не из модели).
- **Конфигуратор фейерверков:** карточка товара получает `effect {heightM, diameterM, durationS, videoUrl, colors[]}`; интерактивный слайдер «ночь/сумерки», видео-превью; предупреждения по безопасности и возрасту обязательны.
- **Календарь клёва:** луна — расчётом (suncalc), температура воды — данные LVĢMC/метео-API, индекс активности = функция (давление, фаза луны, T воды, вид рыбы). Показывать как *ориентир*, не как гарантию. Блок «Как получить Makšķerēšanas karti / e-Loms» — ссылка на официальный ресурс.

## 8. Стек и производительность

Next.js 14 (App Router, RSC), TypeScript, Tailwind, Zustand, TanStack Query, R3F + drei, next-intl (lv/ru/en), Mapbox GL.
3D: модели **glTF/GLB + Draco**, ≤ 400 КБ на рыбу, ленивая загрузка (`next/dynamic`, `ssr:false`), `IntersectionObserver` — Canvas монтируется только при попадании в viewport, fallback — статичная картинка. Цель: LCP < 2.5 с, Hero-картинка `priority`.
Доступность: WCAG 2.1 AA, у 3D-модуля — альтернативный список рыб с клавиатурным выбором.
